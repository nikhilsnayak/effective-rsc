# Decision register

| ID    | Status   | Decision                                                                                                                                                                                                                                              |
| ----- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-001 | Accepted | Build a research framework without production-stability or backward-compatibility guarantees.                                                                                                                                                         |
| D-002 | Accepted | Load one explicit application from `src/application.tsx`; filenames have no other routing semantics.                                                                                                                                                  |
| D-003 | Accepted | Compose immutable `ERSC.Routes` from concern-specific `Page`, `Layout`, `Loading`, `ErrorBoundary`, and `NotFound` values owned by one ERSC identity.                                                                                                 |
| D-004 | Accepted | Stream full-document SSR and embed the same render's Flight for hydration.                                                                                                                                                                            |
| D-005 | Accepted | Use one whole-tree Flight response per v0 navigation; defer partial-route transports and patch models.                                                                                                                                                |
| D-006 | Accepted | Build routing directly on the Navigation API without a History API fallback.                                                                                                                                                                          |
| D-007 | Accepted | Use React Canary, Rsbuild, `rsbuild-plugin-rsc`, and native RSDR; pin React, React DOM, and RSDR to one exact compatible release.                                                                                                                     |
| D-008 | Accepted | Use Effect v4 RC for effectful orchestration and plain TypeScript for pure or incidental code.                                                                                                                                                        |
| D-009 | Accepted | Expose `ERSC.ServerFn.make` as an additive Effect/Schema wrapper while preserving native module references, binding, and inline lexical capture.                                                                                                      |
| D-010 | Accepted | Use `unstable/HttpApi` only for non-UI HTTP routes.                                                                                                                                                                                                   |
| D-011 | Deferred | Consider Effect RPC only for work that does not imply an RSC refresh.                                                                                                                                                                                 |
| D-012 | Accepted | Use TypeScript 7 with strict checking.                                                                                                                                                                                                                |
| D-013 | Accepted | Use Bun as the v0 runtime, Vitest with `@effect/vitest`, and Bun-hosted integration tests.                                                                                                                                                            |
| D-014 | Deferred | SSG, ISR, partial prerendering, SPA mode, alternate bundlers, and runtime adapters.                                                                                                                                                                   |
| D-015 | Accepted | Publish one `effective-rsc` package with explicit internal application, RSC, client, server, and build graphs.                                                                                                                                        |
| D-016 | Accepted | Use one application-scoped `ERSC` authoring module with `Page.make`, `Layout.make`, `Loading.make`, `Component.make`, `ServerFn.make`, and `Routes.make`; component factories run Effect operations while Loading stays synchronous and service-free. |
| D-017 | Accepted | Carry the complete document route tree and React form state in a small native Flight model used by Fizz and hydration.                                                                                                                                |
| D-018 | Accepted | Expose one package-root application API; keep runtime and build subpaths private.                                                                                                                                                                     |
| D-019 | Accepted | Put all generated application output under `.ersc/`.                                                                                                                                                                                                  |
| D-020 | Accepted | Model renderers as Effect services; separate cross-graph contracts from runtime-owned live Layers and provide them to requests.                                                                                                                       |
| D-021 | Accepted | Compose requests in `Application.httpLayer`; let `Application.layer` add Bun listening; export both from the framework RSC entry.                                                                                                                     |
| D-022 | Accepted | Declare the complete service-contract universe once with `Application.ersc<Services>()`, validate every component and ServerFn operation against it, and choose a closed implementation Layer only at `ERSC.make({ servicesLayer })`.                 |
| D-023 | Accepted | Use port `18193` for both development and production.                                                                                                                                                                                                 |
| D-024 | Accepted | Use the framework `'use server-entry'` module as compiler and asset owner; pass through the application definition and consume Rspack's asset metadata.                                                                                               |
| D-025 | Accepted | Integrate Tailwind CSS v4 through its Rsbuild plugin and fixed `src/styles.css`; retain native CSS/CSS Modules and React stylesheet resources.                                                                                                        |
| D-026 | Accepted | Treat React, React DOM, Effect, and RSDR as exact shared peers; do not vendor, alias, or re-export them.                                                                                                                                              |
| D-027 | Deferred | Revisit StyleX when its Rspack and watch-invalidation support no longer require a framework bridge.                                                                                                                                                   |
| D-028 | Accepted | Compile exact static paths directly into Effect HTTP; reserve `/_ersc/assets`, preserve Layout/Loading ancestry, and keep native `404` responses.                                                                                                     |
| D-029 | Accepted | Build immutable mountable `ERSC.Routes`: `page` adds a relative destination; `mount` prefixes a non-empty child from the same ERSC identity; nested Layout/Loading are optional; the non-empty root requires a Layout.                                |
| D-030 | Accepted | Render one unary Layout → optional Loading → child chain ending in Page, with Loading below its Layout.                                                                                                                                               |
| D-031 | Accepted | Give each node an opaque role-qualified local React `id`, content, and optional child. Layout/Loading include authored scope identity; Loading/Page include the pathname. Defer slot and patch fields.                                                |
| D-032 | Accepted | Let `NavigateEvent.signal` own the intercepted navigation through its exact layout commit. Await the Flight root, publish once, and resolve Navigation API after that commit; do not claim ownership of nested rows after the handler settles.        |
| D-033 | Accepted | On cross-destination navigation, retain the revealed common Layout prefix while `RouteOutlet` uses the new child. Server Function refresh replaces the complete tree.                                                                                 |
| D-034 | Accepted | Enable React Strict Mode at the browser root and Rspack's built-in React Compiler in development and production. The compiler is browser-only; the RSC and SSR graphs omit it.                                                                        |
| D-035 | Accepted | Bind each application-scoped ERSC runner with AsyncLocalStorage while entering native Flight rendering so every effectful Page, Layout, and Component shares the request runtime and services without prop threading or mutable React cache state.    |
| D-036 | Accepted | Treat `ERSC.ServerFn.make` as a framework intrinsic: expose a real Promise callable to React clients, carry a branded lazy Effect in the server invocation, execute it only in the matching ERSC request runtime, and reject direct server calls.     |
| D-037 | Deferred | Decide whether and how a newer committed route should retire an earlier committed-but-still-streaming Flight response; ordinary RSC navigation does not provide this policy automatically.                                                            |
| D-038 | Accepted | Define ERSC as an application-scoped authoring and execution module owning one service-contract universe, runtime identity, and request-scoped Effect runner; `ERSC.make` closes its authored Routes with a Layer into an executable application.     |
| D-039 | Accepted | Give every render concern a uniform options-object authoring interface: `Component.make({ render })`, `Layout.make({ render })`, `Loading.make({ render })`, and `Page.make({ render })`; retain concern-specific options alongside `render`.         |
