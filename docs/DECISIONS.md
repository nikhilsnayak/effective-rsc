# Decision register

| ID    | Status   | Decision                                                                                                                                                                                                                                              |
| ----- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-001 | Accepted | Build a research framework without production-stability or backward-compatibility requirements.                                                                                                                                                       |
| D-002 | Accepted | Load the explicit `Application.make` definition from fixed `src/application.tsx`; do not infer routes or concerns from any other filesystem structure.                                                                                                |
| D-003 | Accepted | Compose `Page`, `Slot`, `Layout`, `Loading`, `ErrorBoundary`, and `NotFound` values explicitly in the route map rather than assigning concerns through filenames.                                                                                     |
| D-004 | Accepted | Stream full-document SSR for every initial document request and embed that render's Flight payload for hydration.                                                                                                                                     |
| D-005 | Accepted | Use whole-tree Flight responses for client navigation in v0.                                                                                                                                                                                          |
| D-006 | Accepted | Build the client router directly on the Navigation API without a History API fallback.                                                                                                                                                                |
| D-007 | Accepted | Use React Canary with Rsbuild, `rsbuild-plugin-rsc`, and the native `react-server-dom-rspack` runtime; pin the three React packages to exact compatible releases.                                                                                     |
| D-008 | Accepted | Use Effect v4 RC as the core execution model for effectful orchestration; keep pure and incidental code plain.                                                                                                                                        |
| D-009 | Accepted | Name the additive Effect and Schema wrapper for native React Server Functions `ServerFn.make`; completing the wrapper must preserve native module-level references, binding, and inline Server Functions with compiler-captured lexical values.       |
| D-010 | Accepted | Use `unstable/HttpApi` for non-UI HTTP routes, not for pages or Flight.                                                                                                                                                                               |
| D-011 | Deferred | Effect RPC support; it may later serve long-lived or streaming operations but will not replace Server Functions.                                                                                                                                      |
| D-012 | Accepted | Use TypeScript 7 and require strict type checking.                                                                                                                                                                                                    |
| D-013 | Accepted | Use Bun as the sole v0 application runtime. Use Vitest with `@effect/vitest` for tests; integration tests execute the application under Bun.                                                                                                          |
| D-014 | Deferred | SSG, ISR, partial prerendering, SPA mode, alternate bundlers, and runtime adapters.                                                                                                                                                                   |
| D-015 | Accepted | Publish and develop one `effective-rsc` package; preserve application, RSC, browser, server, and build boundaries as explicit internal module graphs rather than workspace packages.                                                                  |
| D-016 | Accepted | Use concern-specific `*.make` factories backed by private shared machinery: Page and Slot render Effect operations, Layout declares slots and renders an Effect operation, and Loading is synchronous.                                                |
| D-017 | Accepted | Serialize a small native Flight payload containing the document root and React form state; pass that form state to Fizz and `hydrateRoot`.                                                                                                            |
| D-018 | Accepted | Expose one root application API from `effective-rsc`; keep its Rsbuild, Bun, browser, RSC, SSR, and shared implementation modules private.                                                                                                            |
| D-019 | Accepted | Use `.ersc/` as the single application build tree for generated artifacts, browser assets, and the Bun server bundle.                                                                                                                                 |
| D-020 | Accepted | Model renderers as Effect services, keep cross-graph contracts separate from their live Layers, provide those Layers to HTTP requests, and launch the server Layer.                                                                                   |
| D-021 | Accepted | Keep request composition in handwritten `Application.httpLayer`; production `Application.layer` adds Bun listening, and the framework RSC entry exports both Layers for `start` and `dev`.                                                            |
| D-022 | Accepted | Require `Application.make` to receive a closed `servicesLayer` whenever route concerns infer Effect services; make it request-visible from the HTTP application scope.                                                                                |
| D-023 | Accepted | Use port `18193` (`R` = 18, `S` = 19, `C` = 3) for the Effective RSC application in development and production; do not expose or require a second application port.                                                                                   |
| D-024 | Accepted | Export the real `ApplicationRoot` Server Component from the framework-owned `'use server-entry'` module and use its Rspack-injected `entryJsFiles` as Fizz bootstrap scripts.                                                                         |
| D-025 | Accepted | Use Tailwind CSS v4 through the official Rsbuild plugin and a fixed application-owned `src/styles.css`; retain Rsbuild's built-in plain CSS and CSS Modules support and emit native React stylesheet resources in full-document SSR.                  |
| D-026 | Accepted | Treat React, React DOM, Effect, and RSDR as exact shared peers: applications declare all four; the framework does not vendor, alias, or re-export them.                                                                                               |
| D-027 | Deferred | Revisit StyleX after its Rspack adapter and server-graph watch invalidation work without a framework-maintained compiler bridge.                                                                                                                      |
| D-028 | Accepted | Register static application paths directly with Effect HTTP; reserve `/_ersc/assets`, inherit root Layout and Loading concerns, and retain native `404` responses.                                                                                    |
| D-029 | Accepted | Represent matched routes as an n-ary tree with named slots. Render route concerns independently in one native Flight model, then recursively stitch them together in the SSR and browser client environments without parent-to-child data waterfalls. |
| D-030 | Accepted | Treat Page as the implicit `children` branch, use `Slot.make` for named parallel branches declared by `Layout.make`, use internal Route outlets as placeholders, and represent intentionally empty slots with `null`.                                 |
